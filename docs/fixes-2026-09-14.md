# 2026-09-14 仓库修复记录

> 本次修复面向在干净环境（例如新克隆的 `c:\workspace\zcode-switcher`）下
> `npm install` / `npm run build` 失败的问题。修复后仓库的 `package.json`
> 与源码能够保持自洽，但安装链仍需要一次重新生成 `package-lock.json`。

## 修复清单

### 1. `package.json` — 错误的版本号

| 包 | 修复前 | 修复后 | 原因 |
|---|---|---|---|
| `lucide-react` | `^1.18.0` | `^0.460.0` | `1.18.0` 在 npm registry 上从未发布过，会 `npm ERR! notarget` |
| `daisyui` | `^5.5.23` | `^4.12.10` | daisyui 5 要求 tailwindcss 4，本项目锁的是 `tailwindcss@3.4.19`；降回 daisyui 4（最后兼容 tailwind 3 的版本） |

`daisyui` 在 `tailwind.config.js` 中的用法（`require("daisyui")` + `plugins: [...]`）
也是 tailwindcss 3 时代的写法，与 daisyui 5 的 CSS-first 插件 API 不兼容，因此
本轮选择降 daisyui 而不是升 tailwind（升 tailwind 需要重写 PostCSS 配置与
`@tailwind` 指令，改动面更大）。

### 2. `scripts/prepare-captcha-runtime.cjs` — 缺失脚本

`package.json` 的 `build:captcha-runtime` 引用了该脚本，但仓库里没有。已新建。
脚本会：

1. 把 `captcha-solver.cjs`（仓库根 / `scripts/` / `src-tauri/` 任一位置）拷贝到
   `scripts/captcha-runtime/captcha-solver.cjs`，与 `src-tauri/src/captcha.rs`
   的 `solver_candidates()` 第三个候选路径对齐。
2. 在 `scripts/captcha-runtime/` 单独 `npm install --no-save jsdom`，因为
   `captcha.rs::solver_is_usable()` 显式要求脚本所在目录有 `node_modules/jsdom`。

### 3. `scripts/captcha-solver.cjs` — 占位实现

该求解器调用第三方打码服务，**不应在公开仓库提供真实实现**。但 captcha.rs
的运行时调度链路需要它存在并能正常退出，否则 `verify_param()` 会立刻报
`未找到验证码求解脚本 captcha-runtime/captcha-solver.cjs`。

本次新增一个**明确标注为 PLACEHOLDER** 的最小 cjs：仅做 jsdom 加载验证
并按协议输出 `VERIFY_PARAM=placeholder-not-a-real-token`。

> ⚠️ 接入真实业务前请用真实求解器覆盖本文件。当前实现永远无法通过任何真实验证。

### 4. `scripts/preview-notice.mjs` — 缺失脚本

`package.json` 的 `notice:preview` / `notice:check` 引用了该脚本。已新建。
脚本：

- 读取 `public/notice.json`；
- 按 `src/lib/notices.ts::parseNotices` 的字段约定（`id/kind/level/title/body`）做校验；
- 默认打印所有启用的通知；`--check` 用于 CI，发现问题 exit 1。

## 还需要你手动处理的事项

1. **重新生成 `package-lock.json`**：
   ```bash
   rm package-lock.json
   npm install
   ```
   原因：lockfile 还锁着不存在的 `lucide-react@1.18.0` 和与本项目 tailwind
   版本不兼容的 `daisyui@5.x`。直接 `npm install` 不会自动重写 lockfile，
   `npm ci` 会失败。

2. **首次构建前初始化 captcha 运行时**：
   ```bash
   npm run build:captcha-runtime
   ```
   这会创建 `scripts/captcha-runtime/node_modules/jsdom`。

3. **`.gitignore` 已正确忽略** `node_modules`、`src-tauri/target`、`dist` 等产物。
   `scripts/captcha-runtime/node_modules` 因为是运行时目录、不会进源码分发，
   建议加进 `.gitignore`：
   ```
   scripts/captcha-runtime/node_modules
   ```
