# 2026-09-15 修复记录：刷新套餐额度失败（HTTP 400 code=3001）

## 现象

安装 1.1.12 后，账号卡片的额度一直显示刷新失败。ZCode 本身已登录、
网络可达 `zcode.z.ai`，但 Switcher 的刷新始终失败，错误为
"套餐额度刷新失败：请打开 ZCode 或切换账号后重试"。

## 根因

billing 接口 `GET /api/v1/zcode-plan/billing/balance` 现在要求请求头
**`X-Device-Mid`**（设备标识）。缺失时服务端返回：

```
HTTP 400  {"code":3001, "msg":"parameter error"}
```

Switcher 的 `quota.rs` 此前只发送 `Authorization: Bearer <zcodejwttoken>`，
因此每次直接请求都被 400 拒绝；日志回退路径（读 `~/.zcode/v2/logs`）只对
"当前登录账号" 生效，刷新非当前档案时彻底失败。

对照实验（用本机真实凭据做的变体测试）：

| 请求形态 | 结果 |
| --- | --- |
| 只有 Authorization（Switcher 旧行为） | HTTP 400 code=3001 |
| + 全套 ZCode 头但无 X-Device-Mid | HTTP 400 code=3001 |
| + **X-Device-Mid**（其余什么都不加） | **HTTP 200 code=0 balances=3** |
| 垃圾 token / 无 Authorization | HTTP 401 |

`X-Device-Mid` 的值与 ZCode 桌面端同源：`~/.zcode/v2/telemetry-state.json`
的 `deviceMid` 字段（ZCode 用 `buildZCodeSourceHeaders` 在每个 API 请求上带它）。

## 修复内容

1. `src-tauri/src/quota.rs`
   - 新增 `read_device_mid()` / `parse_device_mid()`：从 telemetry-state.json
     读取设备标识；
   - `fetch_quota` 构建 reqwest Client 时通过 `default_headers` 注入
     `X-Device-Mid`；
   - `APP_VERSION_CANDIDATES` 增加 `"3.11.2"`（当前 ZCode 版本）并放在首位；
   - 新增单元测试 `parse_device_mid_from_telemetry_state` 与
     `#[ignore]` 真机测试 `fetch_quota_real_credentials`。
2. `src-tauri/src/lib.rs`
   - `run()` 支持 `--quota-probe` 子命令：无窗口地跑一次真实刷新并打印
     套餐/额度（不打印任何 token），供真机验证。

## 验证

```
$ zcode-switcher.exe --quota-probe
刷新结果: 成功
套餐: Some("ZCode Global Build")
状态: Some("active")
额度条目 (3):
  - GLM-5.3-Flash    剩余  100000000 /  100000000 (-)
  - GLM-5.3          剩余    3000000 /    3000000 (-)
  - GLM-5.3-Flash    剩余    5000000 /    5000000 (-)
```

`windows-regression.ps1`：10 项检查 9 项 PASS（唯一 FAIL 是
`zcode.cdp`，即 ZCode 未开 9229 远程调试端口，与额度刷新无关，
属于"无感切换"功能的依赖）。

## 附注

- 该接口限流较严（连续请求会 429），`get_with_retry` 已有 Retry-After 退避。
- `scripts/quota-probe.mjs` 是排查时的 Node 版对照探针（解密凭据后直接
  调 API），保留作为诊断工具；正式验证请用安装后的
  `zcode-switcher.exe --quota-probe`。
- cargo test 在 GNU 工具链下无法运行：测试 exe 不带 comctl32 v6 manifest，
  静态导入 `TaskDialogIndirect` 解析失败（STATUS_ENTRYPOINT_NOT_FOUND）。
  MSVC 工具链不受影响；GNU 环境下请用 `--quota-probe` 做运行时验证。

# 2026-09-15 第二批：跨机器/虚机迁移与验证码自动化

目标：让账号（含体验套餐额度）能迁移到任意 Win11 / Linux 虚机，并在虚机里
绕过人工认证框使用额度。

## 机制结论（先记结论再记改动）

- 套餐用量在服务端、按账号计；本地等价物是 `~/.zcode/v2/credentials.json`
  （AES-256-GCM 加密的 JWT / OAuth 令牌，密钥派生自
  `zcode-credential-fallback:<平台>:<主目录>:<用户名>` 或
  `ZCODE_CREDENTIAL_SECRET`）。`~/.zcode/v2/certs/` 是 ZCode 自己的网络 CA，
  与账号无关。
- 因此**裸拷贝 credentials.json 只在"平台+主目录+用户名"完全一致时有效**；
  跨平台/换用户名必须走"解密导出 → 目标机重加密导入"（export/import 已内置）。

## 改动

1. `quota.rs` —— deviceMid 兜底 + 凭据签发时间
   - 干净机器（没跑过 ZCode 桌面端）上 `telemetry-state.json` 不存在，
     billing 接口会因缺 `X-Device-Mid` 返回 400 code=3001。现在缺失时自动
     生成 UUID v4 形态的设备标识并持久化到 `~/.zcode/v2/zcode-switcher-device.json`，
     之后每次请求复用同一个值。
   - `QuotaInfo` 新增 `token_issued_at`（JWT `iat`），前端在账号卡片显示
     "凭据签发 日期"，用于跨机器导入后判断凭据新旧。
2. `captcha.rs` + `public/captcha-solver.html` —— 验证码求解真实化
   - 原 `captcha-solver.cjs` 是占位实现（输出假 token），自动求解从未真正可用。
   - 新增首选通道：隐藏 WebView 窗口加载 `captcha-solver.html`，在真实浏览器
     环境（WebView2 / WebKitGTK）里加载阿里云验证码 SDK 并触发无痕验证，
     通过 `captcha_solver_result` IPC 命令回传 verify param；不依赖目标机
     装有 node。45 秒超时后回退 node 求解器（开发/无窗口场景兜底）。
   - 同账号重试、参数一次性消费的语义不变。
3. `proxy.rs` —— 本地网关拆分重开
   - 上游只剩账号池 ZCode JWT，删除外部 API Key 供应商转发链路及其辅助函数
     （`Upstream::CustomProvider`、`anthropic_to_openai_body` 等）；
     `models`/`health` 相应收敛。
   - 删除"[临时调试]"把上游响应体写入 `%TEMP%/zcode-proxy-debug.log` 的逻辑
     （会把对话内容落盘明文文件，属于安全隐患）。
   - 转发错误信息带上账号名，多账号池排障更直接。
   - 前端 `LOCAL_API_FEATURE_ENABLED = true`，"本地 API 服务"+"账号池"卡片
     恢复显示；API Key 供应商入口保持独立关闭（`PROVIDER_FEATURE_ENABLED`）。
4. 打包 —— `tauri.conf.json`
   - `bundle.resources` 加入 `../scripts/captcha-runtime`（随安装包带
     jsdom 运行时）；
   - `beforeBuildCommand` 追加 `node scripts/prepare-captcha-runtime.cjs`，
     CI 无需手工预生成。
5. 导出文件安全 —— `profile.rs` + 前端
   - 新命令 `delete_account_export_file`：只删 schema 匹配
     （`zcode-switcher-account/v1` / `zcode-switcher-accounts/v1`）的便携
     导出文件，防止被当"按路径删任意文件"使用。
   - 导入成功后询问是否就地删除源导出文件；导出成功后提示"文件含明文凭据"。
6. `scripts/run-tests.sh` —— GNU 工具链跑单测的辅助脚本
   - `cargo test` 的测试 exe 无 comctl32 v6 manifest，静态导入
     `TaskDialogIndirect` 解析失败（0xc0000139）。脚本先 `cargo test --no-run`，
     把 `scripts/testexe.manifest` 放到测试 exe 旁（SxS 自动加载外置
     manifest），再直接运行。本机 32 个单测全部通过。
   - 附带修复了 quota 测试模块里 UNIX_EPOCH 导入等小问题。
7. 文档 —— `docs/usage.md` 新增「跨机器 / 虚机迁移账号」章节；
   `INSTALL.md` 故障排查表同步 run-tests.sh。

## 验证

- `bash scripts/run-tests.sh`：32 passed, 1 ignored（真机 quota 测试）。
- `npx tsc --noEmit` + `npm run build`：通过，`dist/captcha-solver.html` 生成。
- `zcode-switcher.exe --quota-probe`：见下（回归验证节）。

## 已知边界

- 隐藏 WebView 无痕验证依赖风控打分，若被判为高危会弹滑块——隐藏窗口无人
  交互，会在 45 秒超时后回退 node 求解器；都失败时网关返回明确的
  "账号池触发验证码校验"错误。需要长时间观察真机命中率。
- `--quota-probe` 在无 Tauri 窗口环境跑不了 WebView 求解，但查额度本就
  不需要验证码。

# 2026-09-15 第三批：验证码求解对齐智谱官方客户端（真机验证通过）

用户指出"要处理的是智谱的验证码"。从本机 ZCode 桌面端
（`C:\Program Files\ZCode\resources\app.asar`，Electron）反解出智谱
官方的验证码接线，逐项对齐后用真实浏览器实测拿到有效 param。

## 官方实现（app.asar 反解结论）

- SDK：`https://o.alicdn.com/captcha-frontend/aliyunCaptcha/AliyunCaptcha.js`，
  init 前设 `window.AliyunCaptchaConfig = { region, prefix }`；
- 回调：`success(param字符串) / fail / onError`（不是 captchaVerifyCallback 形态）；
- 触发：`instance.startTracelessVerification()`（无痕验证）——
  实例方法表里根本没有 `verify()`；旧占位方案若真接入也只能失败；
- 节奏：SDK 加载后至少等 2 秒再触发（wat()），实例等待 10 秒（pX），
  无痕无响应 8 秒转交互（mX），整体 120 秒（pat）；
- fail 事件解析：`{success, verifyResult, verifyCode, certifyId}`；
  `success&&verifyResult` 或 `verifyCode==='T006'` 时事件上带
  `captchaVerifyParam` 可直接采用（terminal pass）；F008 = 重复提交
  （certifyId 与上一轮相同即告警）；
- 配置：configs API `data.configs.captcha = {enabled, region, prefix, sceneId}`，
  `enabled===false` 或字段缺失 = 无需验证码（nZ()）；
  **线上 region 现为 "cn"**（`{"enabled":true,"prefix":"no8xfe","region":"cn","sceneId":"11xygtvd"}`），
  旧默认 "sgp" 已过时；
- 请求头（buildZCodeSourceHeadersFromContext + RX()）：
  `X-Aliyun-Captcha-Verify-Param` + **`X-Aliyun-Captcha-Verify-Region`**，
  外加 `User-Agent: ZCode/<版本>`、`X-ZCode-App-Version`、
  `X-Platform: <platform>-<arch>`、`X-Os-Category`、`X-Device-Mid` 等一整套。

## 对齐改动

1. `public/captcha-solver.html` 重写：
   - 设 `window.AliyunCaptchaConfig`；success/fail/onError 回调（保留
     captchaVerifyCallback 兼容）；`startTracelessVerification()` 触发；
     2 秒节奏；fail 事件 terminal pass / F008 解析。
2. `captcha.rs`：
   - `CaptchaConfig` 增加 `language` 与 `captcha_required`（enabled 语义）；
     默认 region 更新为 "cn"；
   - 新增 `VerifyParam { param, region }` 与 `verify_param_if_required()`：
     返回 `Ok(None)` 表示上游未启用验证码，请求直接不带验证码头；
   - `ZCODE_APP_VERSION` 更新为 3.11.2。
3. `proxy.rs` 转发请求：
   - 验证码头补 `X-Aliyun-Captcha-Verify-Region`；
   - 补齐官方来源头：`x-device-mid`、`x-platform`（win32-x64 等）、
     `x-os-category`，UA/版本号升级 3.11.2；
   - `quota.rs` 暴露 `device_mid_for_requests()` 供其取同源设备标识。
