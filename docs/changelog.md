# 更新日志

## 1.1.16

- 低额度自动切换的目标余额强制复核：切套餐前重新拉取当前账号最新余额，复核通过才执行切套餐（复核发现当前入口已恢复则不动，目标入口复核不合格则直接落入切账号流程）；切账号时候选按余量排出验证顺序后逐一重新拉取最新余额，只有 token/积分仍全部高于阈值的账号才允许成为目标，全部验证不通过则进入自动暂停——杜绝凭过期缓存"从一个没余额的账号切到另一个没余额的账号"。
- 审计修复：套餐切换冷却时间戳改为只在真正执行切换时记录。此前一次"复核不动"（目标已耗尽/余额已恢复）也会消耗 60 秒冷却，期间切套餐和切账号全部被阻塞。
- 新增 store 级集成回归 `scripts/auto-switch-regression.mjs`（`npm run test:autoswitch`）：真实 zustand store + 桩 tauri 命令，覆盖逐一验证选首个合格者、全部复核不合格暂停不切换、复核轮次不消耗冷却、切套餐失败落入切账号四类布线场景。
- 修复设置面板回归脚本的偶发失败：固定 sleep 等待 React 重渲染在负载高时不够（实测 ~20% 失败率），改为轮询等待。
- 修复 `windows-regression.ps1` 在 Windows PowerShell 5.1 下因无 BOM 的中文被按 GBK 误读导致的解析失败；默认期望版本同步为 1.1.16。

## 1.1.15

- 修复系统托盘出现两个图标的问题：tauri.conf.json 的声明式 trayIcon 与代码里的 setup_tray 重复创建，移除配置项，只保留带「显示/退出」菜单的程序化托盘。
- 账号自动合并：修复同一账号"一条档案存了邮箱、另一条只有用户 ID"被判定为两个账号的问题（旧版按单一身份键去重漏判）。现改为身份信号（邮箱/手机号/用户 ID 任一重叠）并查集分组，主档案吸收空缺字段与缺失的 apiKey 快照；应用启动时自动迁移收敛一次，合并前自动备份到 account-backups/。
- 保存/导入/切换/活跃判定全部改用身份信号重叠匹配，重新捕获同账号不再产生新档案。
- 版本号引入编译次数：显示为「版本+编译次数」（如 1.1.15+43），每次 `tauri build` 自动递增（scripts/stamp-build.mjs + build.count）；+N 为 semver 构建元数据，不影响自动更新的版本比较。
- 设置面板版本显示规范化为 `v1.1.15+N`。

## 1.1.14

- 修复个人套餐积分显示不随 5 小时窗口变化的问题：积分改用 OAuth token 查询官网同源的 quota/limit 接口（实时窗口明细），原 mcp/usage 汇总仅作兜底。
- 个人套餐积分按窗口拆分显示：5小时积分、周积分、月积分；MCP 月度工具额度单独展示。
- 低额度自动切换：任一积分窗口（5小时/周/月）剩余低于积分阈值即触发切换；积分链路失败时错误信息透出真实原因。

- 低额度自动切换改为“先切套餐、后切账号”：判定对象改为 ZCode 当前选中的套餐入口，当前入口余额不足时先切换到同账号内仍有余额的另一个套餐入口（Start Plan 入口 ↔ GLM Coding Plan 入口），账号内所有套餐都低于阈值后才切换账号。
- 新增“低额度时动作”设置：除自动切换外，可选择“暂停执行”——余额低于阈值时本地网关拦截所有模型请求（非流式 429 / 流式 SSE error），同时停止自动切换并提醒，**等待人工操作才解除**。
- 实测 ZCode 不监听 setting.json 外部修改：套餐切换优先通过 CDP 注入渲染层 settingService 实时生效（无需重启），不可用时退回写配置文件并在开启自动重启时自动重启 ZCode。
- 新增真机自测命令：`--guard-selftest`（网关拦截链路）、`--plan-switch-probe`（套餐切换落盘验证）。
- 审计修正：暂停模式不再污染全局 `autoSwitchPaused` 标志（该标志语义是“所有账号 Token/积分均低于阈值”）；`isCurrentEntryLow` 在当前入口无数据时回退到整账号判定，避免账号只订阅单套餐时自动切换失灵；不再以可能过期的 Coding Plan API Key 本地快照阻断套餐切换。
